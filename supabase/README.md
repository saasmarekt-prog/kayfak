# Supabase database foundation

الملفات `migrations/0001_phase2_core_schema.sql` حتى `migrations/0008_room_moderation_actions.sql` هي migrations الأساس الحالية. صُممت لتكون صغيرة وقابلة للمراجعة، وليست مخطط المنتج النهائي.

## النطاق

يشمل المخطط الحالي:

- `profiles`: ملف المستخدم المرتبط بـ`auth.users`.
- `follows` و`blocks`: علاقات المستخدم الأساسية.
- `communities` و`community_members`: المجتمعات والعضوية والأدوار.
- `rooms` و`room_members`: الغرف ودورة العضوية.
- `reports`: البلاغات التي ينشئها المستخدم.
- `notifications`: إشعارات المستخدم الخاصة.

تضيف migration السادسة محرك القصص بالإصدارات والمشاهد والاختيارات والتقدم، ومحرك الألعاب بجلسات وجولات وإجابات لا تكشف الإجابة الصحيحة للعميل، وحسابات نقاط وسجل مكافآت.

تضيف migration السابعة طلبات التحدث، موافقة المشرف، وتغيير دور العضو بين مستمع ومتحدث مع حماية مالك الغرفة.

تضيف migration الثامنة الحظر والطرد وسجل إجراءات الإشراف. الحظر يمنع إعادة الانضمام عبر `join_room`، والطرد يخرج العضو من سجل العضوية، وEdge Function `functions/moderate-room-member` تحاول إزالة المشارك المتصل من LiveKit عبر RoomService API.

تضيف migration الثانية دالة `discover_public_rooms` لاكتشاف الغرف العامة الحية مع بحث اختياري وصفحات وعدّاد مستمعين محسوب من العضويات النشطة. الدالة متاحة للزائر للغرف العامة فقط، ولا تعطي وصولًا إلى الجداول الخاصة.

تضيف migration الثالثة دورة حياة الغرفة، الدعوات الخاصة، المشرفين، وجلسات الصوت metadata. تسجيل جلسة الصوت محصور بـ`service_role` حتى لا يستطيع العميل إعلان غرفة مباشرة دون نجاح مزود الصوت. التفاصيل التشغيلية موجودة في `docs/room-audio-lifecycle.md`.

تضيف migration الرابعة مواضيع المجتمعات وردود الفعل ومسارات إنشاء المجتمع والعضوية والنشر. تضيف migration الخامسة محفظة ودفتر قيود immutable والهدايا والمشتريات والاشتراكات، مع حصر التسويات المالية بالخادم الموثوق. توجد Edge Functions في `functions/livekit-token` و`functions/livekit-webhook` و`functions/send-gift` و`functions/billing-webhook` و`functions/submit-game-answer`.

## قرارات أمان مهمة

1. كل جدول مفعّل عليه RLS، ولا توجد صلاحيات `anon` على جداول التطبيق.
2. القراءة العامة مقيدة بالغرف العامة والملفات الشخصية العامة؛ الغرف الخاصة والمجتمعات الخاصة تحتاج علاقة عضوية.
3. لا توجد سياسة `INSERT` مباشرة على `room_members`. الانضمام يتم عبر `join_room(uuid)` التي تتحقق من المصادقة والحالة والسعة داخل معاملة وقفل صف الغرفة.
4. `leave_room(uuid)` يضع `left_at` بدل حذف السجل، للحفاظ على سجل العضوية.
5. إنشاء مستخدم جديد ينشئ ملفًا تلقائيًا عبر trigger على `auth.users`.
6. إنشاء مجتمع أو غرفة يضيف المالك كعضو تلقائيًا عبر trigger بصلاحيات محدودة.
7. مفاتيح `SECURITY DEFINER` تضبط `search_path` إلى `public`، ولا تعرض أسرارًا للعميل.
8. اختيار القصة يمر عبر `choose_story_choice` مع قفل تقدم المستخدم والتحقق من انتقال العقدة ومنع تكرار طلب التسوية. إجابات الألعاب تُصحح عبر Edge Function موثقة ولا تمنح النقاط من العميل.

## التطبيق المحلي

يحتوي `config.toml` على إعدادات Supabase المحلية لـAPI وPostgres وAuth وRealtime وEdge Functions. يحتوي `seed.sql` على قوالب ألعاب وقصة تجريبية مشروطة بوجود profile محلي، ولا ينشئ مستخدمين أو أسرارًا تلقائيًا. دليل التشغيل الكامل موجود في `docs/supabase-local-setup.md`.

بعد ربط مشروع Supabase:

```bash
supabase link --project-ref YOUR_PROJECT_REF
supabase db push
supabase test db
```

لا تطبق SQL يدويًا من لوحة Supabase. راجع migration أولًا، ثم استخدم Supabase CLI وسجل نتيجة التطبيق في بيئة اختبار منفصلة.

لم تُشغّل هذه الجلسة migration على مشروع Supabase حقيقي لعدم توفر `project-ref` أو جلسة Supabase CLI. لذلك لا يوجد ادعاء بأن الجداول أو السياسات منشورة حاليًا.

## قبل الإنتاج

- إضافة اختبارات RLS بمستخدمين ومجتمعات وغرف fixture حقيقية، لا الاكتفاء بفحص وجود السياسات.
- إضافة نظام دعوات للغرف الخاصة قبل السماح بمشاركة روابطها.
- تقييد تغيير أدوار المجتمع والغرفة عبر دوال خلفية مخصصة؛ لا يكفي `UPDATE` المباشر في المرحلة التالية.
- إضافة rate limits وقيود مكافحة spam عبر Edge Functions أو طبقة API موثوقة.
- مراجعة سياسات حذف الحساب والاحتفاظ بالبلاغات وسجل التدقيق.
- اختبار Edge Functions ومزودي LiveKit وStripe في مشروع staging قبل الإنتاج، مع ضبط الأسرار عبر `supabase secrets set` وعدم وضعها في GitHub.
- إنشاء محتوى قصص وجولات ألعاب من لوحة إدارة موثوقة أو seed تطويري متحقق، ثم اختبار الانتقالات والإجابات والتزامن والمكافآت قبل النشر.
