# دورة حياة الغرفة والصوت

تضيف migration `0003_room_lifecycle_audio.sql` مسارًا صريحًا وآمنًا للغرف الخاصة والصوت. تبدأ الغرفة كـ`draft` عبر `create_room`; لا يستطيع تطبيق الهاتف إدخال سجل غرفة مباشرة أو تغيير حالتها إلى `live`.

## العضوية

الغرفة العامة تسمح بالانضمام إذا كانت `live` ولم تتجاوز السعة. الغرفة الخاصة تحتاج دعوة غير مسحوبة من `room_invites`. الانضمام والمغادرة يمران عبر دوال ذرية، ولا توجد سياسات إدخال أو تعديل أو حذف مباشرة لعضوية الغرفة من العميل.

يمكن للمالك أو المشرف دعوة مستخدم عبر `invite_user_to_room`. صلاحيات المشرفين محفوظة في `room_moderators` ولا يستطيع العميل منح نفسه دورًا.

## الصوت

`room_audio_sessions` يحفظ metadata فقط: المزود، معرّف غرفة المزود، الحالة والتوقيت. لا يخزن access tokens أو مفاتيح LiveKit أو أي سر.

التدفق المقصود هو:

1. ينشئ العميل غرفة `draft` عبر `create_room`.
2. تستدعي Edge Function موثوقة مزود الصوت وتنشئ غرفة LiveKit.
3. بعد نجاح المزود، تستدعي Edge Function `register_audio_session` بصلاحية `service_role`، فتتحول الغرفة إلى `live`.
4. تصدر Edge Function رمز اتصال قصير العمر للمستخدم بعد التحقق من عضويته، ولا يمر الرمز عبر SQL أو التطبيق كسر ثابت.
5. عند انتهاء الصوت، تسجل Edge Function الحالة `ended` وتغلق الغرفة عبر نفس المسار.

لم يتم إنشاء Edge Function أو إضافة مفتاح مزود صوت في هذه المرحلة. لذلك لا ينبغي عرض الغرفة على أنها بث صوتي حقيقي حتى يكتمل تكامل المزود.
